# Работа с панелью

## Вкладки

Верхняя строка — вкладки: **Обзор** и по одной на каждый хост. Цвет точки у хоста: зелёный — замечаний нет, жёлтый — есть средние, красный — высокие или хост не опрашивается; число — количество высоких и средних замечаний. Значок `✎N` — у хоста есть подготовленные, но не применённые изменения.

**Обзор** показывает сводку по всем хостам, карточки хостов и сравнительную таблицу. «Опросить все» подключается ко всем хостам параллельно и обновляет состояние.

Внутри хоста — разделы:

| Раздел | Что там |
|---|---|
| **Сводка** | плитки состояния, состав портов, замечания с кнопками исправления, сведения о хосте, проверка доступа панели по SSH |
| **Порты** | таблица «порт → разрешён ли в зоне → кто слушает → Docker → итог»; фильтры, поиск, открыть/закрыть порт |
| **Зоны** | зоны firewalld и всё, что в них настраивается; зона по умолчанию и LogDenied; расхождения runtime/permanent; политики |
| **iptables** | таблицы и цепочки IPv4/IPv6 со счётчиками; удаление правил до перезагрузки; прямые правила firewalld |
| **nftables** | список таблиц и просмотр любой из них |
| **SELinux** | режим, переключатели, метки портов, поиск типа по порту, отказы AVC |
| **fail2ban** | jails, заблокированные адреса, исключения |
| **Журнал** | транзакции на самом хосте и действия, сделанные через панель |

Кнопка **Обновить** опрашивает хост заново; **Отчёт** — HTML или PDF; **Хост** — свойства хоста.

## Как читать таблицу портов

| Итог | Значит |
|---|---|
| открыт · слушает | порт разрешён в зоне, смотрящей в сеть, и его слушает процесс |
| никто не слушает | порт открыт в зоне, но сейчас его никто не слушает — кандидат на закрытие |
| закрыт firewall | процесс слушает внешний адрес, но зона его не пропускает |
| Docker в обход зон | порт опубликован контейнером (DNAT в цепочке `DOCKER`) — он доступен из сети, даже если его нет в зоне |
| без firewall | firewalld выключен — порт доступен всем |

«Смотрящие в сеть» зоны — те, к которым привязан физический интерфейс или источники, плюс зона по умолчанию. Временные UDP-порты (≥ 32768) скрыты; включаются флажком.

Порты Docker нельзя закрыть в зоне — ограничьте их в `docker-compose` привязкой к адресу (`127.0.0.1:3000:3000`) или правилом в политике/зоне `docker`.

## Изменения: очередь → транзакция → подтверждение

1. Любое действие (закрыть порт, добавить службу, переключить boolean…) **не применяется сразу**, а попадает в очередь. Внизу появляется панель «Подготовлено изменений: N». Изменения, отменяющие друг друга, сокращаются.
2. **Применить…** показывает список с пометками риска («затрагивает SSH», «закрывает доступ»…), таймер отката и флажок автоподтверждения.
3. Панель отправляет всю очередь на хост одной транзакцией. helper:
   - сохраняет копию `/etc/firewalld` и ставит таймер отката;
   - выполняет действия, записывая для каждого обратное;
   - проверяет, что SSH для панели остаётся открытым — сейчас и после перезагрузки;
   - при ошибке на любом шаге возвращает всё сделанное.
4. **Автоподтверждение** (по умолчанию включено): через полторы секунды панель открывает *новое* SSH-соединение и подтверждает транзакцию. Если подключиться не удалось — подтверждения нет, и через время таймера хост откатит изменения сам.
5. Без автоподтверждения внизу появится полоса с обратным отсчётом и кнопками **Подтвердить** / **Откатить**.

По умолчанию изменения в зонах применяются «постоянно» — и в текущей, и в сохранённой конфигурации. Переключатель в разделе «Зоны» позволяет менять только текущую («до перезагрузки»). Удаление правил iptables всегда действует только до перезагрузки.

Таймер отката задаётся в настройках панели (30–600 секунд, по умолчанию 60) и в окне применения.

## Типовые задачи

**Закрыть порты, которые никто не слушает.** Сводка → замечание «Открыто в firewall, но никто не слушает» → «Разобрать…» → отметить → «Добавить в очередь» → «Применить…».

**Разрешить SSH только из домашней сети.** Зоны → public → «Добавить правило…»: источник `192.168.1.0/24`, служба `ssh`, `accept` → в очередь; затем убрать службу `ssh` из зоны → применить. Если адрес панели не попадает в источник, helper откажется применять.

**Включить firewalld на хосте, где он выключен.** Сводка → «firewalld выключен» → «Включить…» — в очередь встанут запуск и автозапуск. Firewalld применит зону по умолчанию (обычно `public` с `ssh`).

**Веб-служба на нестандартном порту с SELinux.** SELinux → «Метки портов»: тип `http_port_t`, порт `8585` → «Пометить»; поиск ниже подскажет, какой тип у порта сейчас.

**Снять бан fail2ban.** fail2ban → крестик у адреса → применить.

**Убрать блокировку, поставленную Wazuh (`firewall-drop`).** iptables → таблица `filter`, цепочка `INPUT` → корзина у правила `-s <адрес> -j DROP` → применить. Действует до перезагрузки.

## Хосты

**+ Хост** — добавить хост: имя, адрес, порт SSH, пользователь (пусто — из настроек панели, по умолчанию `sec_fw-admin`), роль, расположение, метки, описание. В свойствах хоста: **Проверить** (подключение и версия helper), **Сбросить отпечаток** (если хост переустановлен и его SSH-ключ сменился), **Удалить** (только из панели; на хосте ничего не меняется).

Флажок «Демо-режим» в свойствах хоста включает работу на сохранённых данных без подключения.

## Настройки панели

Шестерёнка справа вверху: пользователь SSH и порт по умолчанию, путь к ключу внутри контейнера (`/data/keys/zaslon_ed25519`), таймер отката, автоподтверждение, демо-режим для всех хостов. Там же — открытый ключ панели.

Значок журнала рядом — все действия панели по всем хостам: добавление и правка хостов, изменения, подтверждения, откаты.

## Отчёт

«Отчёт» → «Открыть HTML», «Скачать HTML» или «Скачать PDF». Отчёт строится по последнему собранному состоянию — перед ним стоит нажать «Обновить». PDF формируется Chromium внутри контейнера; если образ собран с `ZASLON_WITH_PDF=0`, откройте HTML и сохраните его в PDF печатью браузера.

## Где панель хранит данные

Всё — в `./data` рядом с `docker-compose.yml` (в контейнере — `/data`):

| Файл | Что |
|---|---|
| `hosts.json` | список хостов и их свойства |
| `settings.json` | настройки панели |
| `state/<id>.json` | последнее собранное состояние хоста |
| `audit.jsonl` | журнал действий панели |
| `known_hosts` | отпечатки SSH-ключей хостов |
| `keys/` | ключ панели |
| `seed.json` | начальный список хостов (используется, пока нет `hosts.json`) |
