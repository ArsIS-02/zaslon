# Решение проблем

Журнал контейнера — первое, куда смотреть:

```bash
cd ~/zaslon && docker compose logs --tail 50
```

## Панель

**Не могу войти: какой пароль?**
Пароля по умолчанию нет — он сгенерирован при первой установке и лежит в `~/zaslon/.env` на хосте панели: `grep ZASLON_PASSWORD ~/zaslon/.env`. Логин — `admin`. Как сменить — в [установке](install.md#вход-в-панель-и-пароль).

**«ZaSlon: пароль не задан … доступ только с самого хоста»**
В `.env` нет `ZASLON_PASSWORD` или контейнер запущен без `.env`. Задайте пароль и выполните `docker compose up -d`.

**Контейнер перезапускается, в журнале `PermissionError: … /app/app/__init__.py`**
Исходники скопированы с правами `0600`, а контейнер работает не от root. Начиная с первой опубликованной версии образ сам выставляет права при сборке; на старой копии: `chmod -R a+rX app static host && docker compose up -d --build`.

**На карточках хостов «Ошибка SSH (код 255): No user exists for uid 1000»**
В образе нет пользователя с UID контейнера, а `ssh` без него не работает. Образ создаёт пользователя по `ZASLON_UID`/`ZASLON_GID` при сборке — пересоберите: `docker compose up -d --build`. Если меняли UID в `.env`, пересборка нужна всегда.

**«Нет ключа панели …»**
В `data/keys/` нет `zaslon_ed25519`. Запустите `zaslon-deploy.sh` или скопируйте ключ вручную (`chmod 600`, владелец — пользователь из `ZASLON_UID`).

**PDF не скачивается: «В контейнере нет Chromium»**
Образ собран с `ZASLON_WITH_PDF=0`. Откройте HTML-отчёт и сохраните в PDF печатью браузера или пересоберите с `ZASLON_WITH_PDF=1`.

## Подключение к хостам

| Сообщение | Причина | Что сделать |
|---|---|---|
| Ключ панели не принят | на хосте нет ключа, панель ходит не с адреса из `from=`, или хост подготовлен старой версией | `bash scripts/zaslon-provision.sh` для этого хоста; проверьте адрес панели (`-z`) |
| Соединение отклонено | sshd не запущен или адрес панели в бане fail2ban (правило REJECT) | на хосте: `sudo fail2ban-client unban <адрес панели>`; убедитесь, что адрес в `ignoreip` |
| Хост не отвечает по SSH | хост выключен, порт закрыт firewall или бан правилом DROP (fail2ban, Wazuh) | проверьте `sudo iptables -S \| grep <адрес>`, `sudo firewall-cmd --list-rich-rules` |
| Отпечаток SSH-ключа хоста изменился | хост переустановлен (или подмена) | убедитесь, что это ваш хост → свойства хоста → «Сбросить отпечаток» |
| sudo требует пароль | нет `/etc/sudoers.d/zaslon` | `bash scripts/zaslon-provision.sh` |
| На хосте нет zaslon-helper | хост не подготовлен | `bash scripts/zaslon-provision.sh` |
| ZaSlon: команда не разрешена | к ключу привязана обёртка, а запрошена неизвестная команда | обновите панель и helper до одной версии |

## Скрипты

**`zaslon-diag.sh`: «Connection closed» или «отклоняет соединение» до ввода пароля** — похоже на бан. Снимите его с консоли хоста:

```bash
sudo fail2ban-client unban <IP вашего компьютера>
```

и добавьте адрес в `ignoreip` в `/etc/fail2ban/jail.local`. В OpenSSH 9.8+ ещё есть встроенные штрафы (`PerSourcePenalties`) — они снимаются сами через несколько минут.

**`zaslon-diag.sh`: «Нет записи в …/fw-diag»** — каталог стал недоступен на запись. Скрипт сам отложит его как `fw-diag.broken-<время>` и создаст новый; если не получилось — `chmod -R u+rwX ~/ZaSlon`.

**`zaslon-provision.sh`: проверка входа ключом не прошла, а установка — «Готово»** — компьютер, с которого запускали, не попал в `from=` (например, запуск с `--no-mac`). На работу панели это не влияет: проверьте с хоста панели (это делает `zaslon-deploy.sh`).

**`zaslon-deploy.sh`: «не найден docker compose»** — установите плагин Compose v2 (пакет `docker-compose-plugin` из репозитория Docker CE или аналог из репозитория дистрибутива) и проверьте: `docker compose version`.

## Изменения

**«изменение закрыло бы SSH для панели ZaSlon: …»** — helper отказался применять: после изменения панель потеряла бы доступ. Сначала добавьте разрешающее правило для адреса панели (например, rich rule с источником), потом убирайте общее.

**«после перезагрузки SSH для панели ZaSlon был бы закрыт»** — то же для сохранённой конфигурации (например, служба `ssh` убрана только из permanent).

**«Автоподтверждение не прошло»** — панель не смогла открыть новое соединение. Если доступа действительно нет, хост откатит изменения по таймеру; если причина временная — нажмите «Подтвердить» в полосе внизу до истечения времени.

**Транзакция осталась в статусе `applying` или `failed` с `undo_incomplete`** — на хосте: `sudo /usr/local/libexec/zaslon/zaslon-helper rollback <id>`; список — `… zaslon-helper pending` и `history`.

**Изменение target зоны сбросило правила, сделанные «до перезагрузки»** — так работает `firewall-cmd --reload`, которым применяется target. Сохраните нужные runtime-правила до смены target (раздел «Расхождения» в «Зонах»).
