# Модель безопасности

ZaSlon управляет межсетевыми экранами всех хостов, поэтому компрометация панели или её ключа — это доступ к firewall и SELinux на каждом хосте. Ниже — чем ограничен этот доступ и что стоит сделать вам.

## Доступ к панели

- Вход — HTTP Basic, логин `admin`, пароль из `ZASLON_PASSWORD` (генерируется при установке, см. [установку](install.md#вход-в-панель-и-пароль)). Сравнение — за постоянное время.
- Без пароля панель отвечает только на запросы с самого хоста (`127.0.0.1`), из сети — отказ.
- Изменяющие запросы (`POST`, `PUT`, `DELETE`) принимаются только с заголовком `X-Zaslon: 1`, который ставит интерфейс панели. Страница с другого сайта не может его подставить — это защита от CSRF при сохранённом в браузере пароле.
- Сервер сам ограничивает таймер отката (30–600 с), даже если запрос просит меньше.
- Трафик — HTTP. Для доступа извне домашней сети используйте обратный прокси с HTTPS и `ZASLON_BIND=127.0.0.1`.

## Ключ панели и пользователь `sec_fw-admin`

| Мера | Зачем |
|---|---|
| Ключ ed25519 без пароля, только в `data/keys/` панели и в `~/ZaSlon/keys/` вашего компьютера | панель должна подключаться без участия человека |
| `from="<адрес панели>,172.16.0.0/12,127.0.0.1,<ваш компьютер>"` | ключ бесполезен с других адресов; `172.16.0.0/12` — сеть Docker, с неё панель ходит на собственный хост |
| `restrict` | без переадресации портов, агента, X11 и терминала |
| `command="/usr/local/libexec/zaslon/zaslon-ssh"` | с ключом нельзя получить shell: обёртка пропускает только `zaslon-helper` с известными подкомандами и сама подставляет `--peer` из `SSH_CLIENT` |
| `~sec_fw-admin/.ssh` и `authorized_keys` принадлежат root | пользователь не может подменить свои ключи или через ссылки заставить root перезаписать чужой файл при повторной подготовке |
| пароль `sec_fw-admin` заблокирован, пользователь не в `wheel` | вход только по ключу |
| `/etc/sudoers.d/zaslon`: `NOPASSWD` только на `/usr/local/libexec/zaslon/zaslon-helper` | никаких других команд от root |

## zaslon-helper — единственная точка входа с правами root

- Запускается как `python3 -I` (без пользовательских путей и переменных Python) с чистым окружением (`PATH`, `LC_ALL=C`, `HOME=/root`).
- Все внешние команды — списком аргументов, без shell.
- Каждое значение проверяется: имена зон, служб, типов и переключателей — `[A-Za-z0-9_.:+-]`, не начинаются с `-`; порты — число или диапазон 1–65535; адреса — через `ipaddress`; rich rules — без переводов строк и начинаются со `rule`; идентификатор транзакции — строгий формат.
- В аргументах правил iptables и direct запрещены `-t/--table`, `-M/--modprobe` и команды над цепочками (`-A -I -D -R -F -X -N -P -E -L -S -Z`).
- Управлять через `systemctl` можно только `firewalld` и `fail2ban`.
- Таймер отката не короче 30 секунд для любой транзакции.

## Защита от потери доступа

1. Таймер `systemd-run` ставится **до** первого изменения. Если helper упадёт или соединение оборвётся посреди транзакции, хост всё равно откатится.
2. Каждое выполненное действие сразу записывается вместе с обратным в `/var/lib/zaslon/tx/<id>.json`.
3. После применения helper проверяет, что SSH с адреса панели пропускается — в текущей **и** сохранённой конфигурации. Модель учитывает привязку источников, интерфейс маршрута к панели, приоритеты rich rules (deny раньше allow), службы, порты, диапазоны, проброс портов и target зоны. Условия, которые проверить нельзя (destination, mac, ipset), для запрещающих правил считаются сработавшими.
4. Панель подтверждает транзакцию **новым** SSH-соединением. Нет связи — нет подтверждения — откат по таймеру.
5. Политики между зонами и прямые правила не моделируются — от них страхует таймер.

## Что сделать вам

- Задать свой пароль или сохранить сгенерированный; не публиковать `.env`.
- Не копировать ключ панели куда-то ещё. Если ключ утёк — удалите `~/ZaSlon/keys/zaslon_ed25519*`, запустите `zaslon-provision.sh` (создаст новый ключ и заменит `authorized_keys` на всех хостах) и `zaslon-deploy.sh`.
- Если используете Wazuh active response — добавьте адрес панели в `<white_list>`.
- Держать helper актуальным: панель подскажет, если версия на хосте старше.
