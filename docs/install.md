# Установка

Установка идёт в три шага; все три скрипта запускаются с вашего компьютера (macOS или Linux), с которого есть SSH на хосты.

1. **Диагностика** — найти хосты и понять, под каким администратором на них заходить.
2. **Подготовка хостов** — создать на каждом пользователя `sec_fw-admin`, поставить helper и ключ панели.
3. **Установка панели** — собрать и запустить контейнер на хосте с Docker.

## Что нужно

| Где | Что |
|---|---|
| Ваш компьютер | `bash`, `ssh`, `scp`, `ssh-keygen`, `ping`, `nc` (есть в macOS и большинстве Linux) |
| Управляемые хосты | РЕД ОС 8 (или RHEL-подобная система) с firewalld, `python3`, `sudo`; администратор с правом `sudo` |
| Хост панели | Docker с плагином `docker compose`; подойдёт Raspberry Pi 4/5 (arm64) или обычный ПК (amd64) |

Скрипты хранят своё состояние в рабочем каталоге `~/ZaSlon` (другой — через переменную `ZASLON_HOME`):

```
~/ZaSlon/
├── users.conf        IP хоста и его администратор — заполняется при диагностике
├── zaslon.conf       PANEL_HOST=<адрес панели>, KNOWN_USERS="user redos …"
├── keys/             ключ панели zaslon_ed25519 (+ .pub) — закрытый никому не передавайте
├── fw-diag/          отчёты диагностики
├── collect/          состояние хостов после подготовки (JSON)
└── logs/             журналы запусков скриптов
```

## Шаг 1. Диагностика

```bash
bash scripts/zaslon-diag.sh
```

Скрипт:

- берёт IPv4-адреса из `/etc/hosts`, проверяет ping и порт 22 — и сразу показывает признаки бана (fail2ban, DROP/REJECT);
- спрашивает, какие хосты проверить, и **перед каждым подключением** — под каким пользователем входить (меню из известных имён или своё имя);
- отпечатки новых хостов принимает сам (`StrictHostKeyChecking=accept-new`); изменившийся отпечаток известного хоста — отказ;
- на каждом хосте запускает `diag-redos-fw.sh` через `sudo` (только чтение) и забирает отчёт в `~/ZaSlon/fw-diag/`;
- запоминает пары «хост → администратор» в `~/ZaSlon/users.conf`.

Пароль SSH спрашивается не больше двух раз за попытку, чтобы не нарваться на бан fail2ban.

## Шаг 2. Подготовка хостов

```bash
bash scripts/zaslon-provision.sh -z 10.0.0.5     # 10.0.0.5 — хост, где будет работать панель
```

Адрес панели запоминается в `~/ZaSlon/zaslon.conf`; при следующих запусках `-z` не нужен. При первом запуске создаётся ключ панели `~/ZaSlon/keys/zaslon_ed25519`.

На каждом выбранном хосте (пароль SSH и пароль `sudo` администратора — по одному разу) скрипт `host/zaslon-hostsetup.sh`:

- создаёт пользователя `sec_fw-admin` с заблокированным паролем;
- кладёт ключ панели в `~sec_fw-admin/.ssh/authorized_keys` (каталог и файл принадлежат root) с ограничениями `command="/usr/local/libexec/zaslon/zaslon-ssh"`, `restrict` и `from="<адрес панели>,172.16.0.0/12,127.0.0.1,<ваш компьютер>"`;
- ставит `/usr/local/libexec/zaslon/zaslon-helper` и `zaslon-ssh`, разрешает `sec_fw-admin` через `sudo` только helper (`/etc/sudoers.d/zaslon`);
- добавляет адрес панели и вашего компьютера в `ignoreip` fail2ban и снимает с них текущий бан.

После этого скрипт сам входит ключом под `sec_fw-admin` и сохраняет состояние хоста в `~/ZaSlon/collect/<IP>.json` — это проверка, что всё работает.

Флаги: `-a` — все хосты без вопроса, `--no-mac` — не разрешать ключ панели с вашего компьютера, `--remove` — убрать всё с выбранных хостов.

> Если на одном из хостов работает сервер Wazuh с active response, добавьте адрес панели в `<white_list>` в `/var/ossec/etc/ossec.conf` менеджера — иначе Wazuh может заблокировать панель за частые подключения.

## Шаг 3. Установка панели

```bash
bash scripts/zaslon-deploy.sh            # на PANEL_HOST из zaslon.conf
bash scripts/zaslon-deploy.sh -h 10.0.0.7  # или на указанный хост
```

Скрипт спросит пользователя SSH на хосте панели и:

1. скопирует исходники в `~/zaslon` на хосте, ключ панели — в `~/zaslon/data/keys/`;
2. при первой установке создаст `~/zaslon/.env` — **с паролем входа в панель** (см. ниже);
3. выполнит `docker compose up -d --build` (через `sudo`, если ваш пользователь не в группе `docker`); первая сборка на Raspberry Pi занимает несколько минут;
4. проверит с хоста панели вход ключом на все хосты из `users.conf`;
5. покажет адрес панели, логин и пароль.

Список хостов для панели берётся из `users.conf` и `/etc/hosts` — при первом запуске панель откроется уже с вкладками всех хостов.

## Вход в панель и пароль

Панель открывается по адресу `http://<хост панели>:8585`. Браузер покажет окно входа (HTTP Basic):

- **логин** — `admin` (меняется переменной `ZASLON_LOGIN`);
- **пароль** — генерируется случайно при первом запуске `zaslon-deploy.sh`: 20 букв и цифр. **Пароля по умолчанию нет.** Скрипт показывает пароль один раз, в конце вывода, а хранится он в `~/zaslon/.env` на хосте панели:

```bash
ssh <пользователь>@<хост панели> 'grep ZASLON_PASSWORD ~/zaslon/.env'
```

Повторные запуски `zaslon-deploy.sh` пароль не меняют — существующий `.env` не перезаписывается.

**Сменить пароль:**

```bash
cd ~/zaslon
sed -i 's/^ZASLON_PASSWORD=.*/ZASLON_PASSWORD=новый-пароль/' .env
docker compose up -d          # или sudo docker compose up -d
```

Браузер может помнить старый пароль — откройте панель в приватном окне. Чтобы сгенерировать новый случайный пароль, удалите `.env` и снова запустите `zaslon-deploy.sh`.

**Без пароля.** Если `ZASLON_PASSWORD` пуст или `.env` нет (например, контейнер запущен вручную без него), панель не открывается из сети: на запросы извне она отвечает «пароль не задан», и работает только с самого хоста (`http://127.0.0.1:8585`). Это сделано намеренно: панель управляет межсетевыми экранами всех хостов.

Пароль передаётся по HTTP. В домашней сети этого обычно достаточно; если панель должна быть доступна шире — поставьте перед ней обратный прокси с HTTPS (Caddy, nginx) и ограничьте `ZASLON_BIND=127.0.0.1`.

## Ручная установка (без скриптов)

```bash
git clone https://github.com/ArsIS-02/zaslon.git && cd zaslon
mkdir -p data/keys
cp /путь/к/zaslon_ed25519 /путь/к/zaslon_ed25519.pub data/keys/ && chmod 600 data/keys/zaslon_ed25519
cat > .env <<EOF
ZASLON_UID=$(id -u)
ZASLON_GID=$(id -g)
ZASLON_LOGIN=admin
ZASLON_PASSWORD=$(head -c 32 /dev/urandom | base64 | tr -dc 'A-Za-z0-9' | head -c 20)
TZ=$(timedatectl show -p Timezone --value 2>/dev/null || echo UTC)
EOF
grep ZASLON_PASSWORD .env       # ваш пароль
docker compose up -d --build
```

Хосты добавляются в интерфейсе кнопкой «+ Хост». Хост должен быть подготовлен `zaslon-hostsetup.sh` (или `zaslon-provision.sh`).

## Переменные `.env`

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ZASLON_PASSWORD` | — | пароль входа; без него — доступ только с самого хоста |
| `ZASLON_LOGIN` | `admin` | логин |
| `ZASLON_PORT` | `8585` | порт на хосте |
| `ZASLON_BIND` | `0.0.0.0` | адрес публикации (`127.0.0.1` — только локально, для прокси) |
| `ZASLON_UID`, `ZASLON_GID` | `1000` | от чьего имени работает контейнер; должен совпадать с владельцем `./data` и ключа |
| `ZASLON_WITH_PDF` | `1` | `0` — образ без Chromium (заметно меньше); PDF тогда сохраняется печатью из браузера |
| `TZ` | `UTC` | часовой пояс в отчётах и журналах |

После изменения `ZASLON_UID`/`ZASLON_GID` нужна пересборка: `docker compose up -d --build`.

## Обновление

```bash
git pull
bash scripts/zaslon-provision.sh   # если изменился helper (панель подскажет: «старая версия helper»)
bash scripts/zaslon-deploy.sh      # пересобрать панель; данные и пароль сохраняются
```

## Удаление

```bash
bash scripts/zaslon-provision.sh --remove              # с хостов: sec_fw-admin, helper, sudoers, jail.d/zaslon.local
ssh <пользователь>@<хост панели> 'cd ~/zaslon && docker compose down && rm -rf ~/zaslon'
```

Журнал транзакций на хостах (`/var/lib/zaslon`) и адреса, дописанные в `ignoreip` файла `/etc/fail2ban/jail.local` (если он был), остаются — уберите вручную, если не нужны.
